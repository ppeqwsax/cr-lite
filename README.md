# 皇城对决 · Royale Lite

一个纯网页、可联机对战的轻量版「皇室战争」。没有安装包、没有账号、打开网页就能打。

线上地址：**https://ppeqwsax.github.io/cr-lite/**

- 单人：和 AI 打（简单 / 普通 / 困难）
- 联机：1v1，创建房间拿到 6 位房间码，把码（或邀请链接）发给朋友
- 8 张自定义牌组 · 双路推塔 · 圣水博弈 · 3 分钟常规 + 60 秒加时

## 怎么玩

1. 菜单里先挑 8 张卡组（默认已配好一套）。
2. 点手牌选中一张，再点**自己半场**放下（法术可以丢全图）。
3. 单位会自动沿最近的桥过河，攻击范围内最近的敌人；没有敌人的话就去拆塔。
4. 拆掉对方公主塔得 1 个皇冠；**任意一座公主塔倒下后国王塔就会激活**（开始射击、也可以被攻击），之后单位一律打离自己最近的塔；拆掉国王塔直接获胜。
5. 3 分钟常规时间结束时皇冠多的一方获胜；平局进入 60 秒加时，加时里**先掉任意一座塔**直接判负，时间到还没掉塔就比皇冠。

## 联机实现

联机默认走 **P2P 直连（WebRTC DataChannel）**，连不上时自动退回云中转，**两方面都免费、都不需要自建服务器**：

- 握手：房间码 → Supabase 广播频道 `cr-<CODE>`（6 位，去掉易混淆的 0/O/1/I），只用来交换 WebRTC 的 offer / answer / ICE，之后游戏流量走浏览器直连。
- 直连打开后开两条通道：`cr-ctrl`（可靠有序，走 start/play/deny/over）+ `cr-game`（不可靠不保序，只走快照，丢包不重传）。
- **房主权威**：整局模拟只跑在房主浏览器里，以 20 Hz 下发快照（塔血量、单位坐标、手牌、圣水、计时）。
- **客机本地预测**：点牌瞬间本地扣圣水并画一个半透明「影子兵」，房主确认后无缝换成真实单位；圣水条按时间本地外推，不再一跳一跳。
- **自适应插值**：按实测到包间隔动态调整缓冲（45–120 ms），断档时沿最近速度外推最多 120 ms，画面不会冻住。
- 卡顿兜底：WebRTC 连不上（对称型 NAT / 公司网络）就静默走 Supabase 中转，HUD 上会写「直连」或「中转」。
- 掉线检测：8 秒收不到快照就提示对手掉线；主动退出会广播 `bye`。

实测（同一局，客机点牌到画面出现自己的兵）：

| 链路 | 反馈延迟 |
| --- | --- |
| 影子兵（本地预测） | 8–17 ms |
| P2P 直连后端到端 | 108–133 ms |
| 退回云中转时 | 420–520 ms |

> anon key 是公开键，写在前端的正常做法；真正的 service_role 密钥不在仓库里。

## 本地运行

纯静态项目，直接用任意静态服务器打开即可（不要用 `file://`，联机需要 http/https）：

```bash
npx serve .
# 或
python -m http.server 8080
```

调试用的 URL 参数：

| 参数 | 作用 |
| --- | --- |
| `?autostart=ai&level=hard` | 直接开一局单人 |
| `?autostart=host` | 直接创建房间 |
| `?room=ABC123` | 直接加入指定房间 |

## 技术栈

- 原生 JavaScript（无框架、无构建），HTML5 Canvas 渲染
- `js/data.js` 卡牌与场地数据 / `js/sim.js` 战斗模拟 / `js/render.js` 绘制 / `js/ai.js` AI
- `js/net.js` 手写的 Supabase Realtime（Phoenix 协议）客户端 / `js/p2p.js` WebRTC 直连 / `js/netplay.js` 房间、快照同步与本地预测
- 牌组存 `localStorage['cr-deck-v1']`

## 已知取舍

- 美术是几何色块 + emoji，没有骨骼动画。
- 27 张可组牌、1v1、没有等级与宝箱。
- 客机为插值显示，网络差时单位会有轻微「拖影」，属正常现象。
